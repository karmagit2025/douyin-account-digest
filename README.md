# douyin-account-digest · 抖音账号解读

给定一个抖音号，抓最近 20–30 条视频、下载、语音转文字，合成一份逐条精读的结构化报告——**选型指南、竞品内容情报、行业认知梳理、产品演化史**。

一句话：**把「刷完一个同行的号」这件事，从两小时变成一条命令 + 一篇有依据的报告。**

---

## 为什么需要一个工具

抖音这条路有三道坎，踩过才知道：

| 坎 | 现象 | 本项目的做法 |
|---|---|---|
| **服务端接口关死** | 用 requests 直接打 API → `403 Uifid Not Found`；yt-dlp 报 `Fresh cookies are needed` | 走**真浏览器**（系统 Edge / Chrome），拦页面自己的 XHR |
| **未登录只能看 21 条** | 翻第二页返回 `n=0`，前端根本不发请求 | **扫码登录一次**，登录态持久化复用，翻页直接到几百条 |
| **没有字幕** | `is_subtitled=0`，`caption` 字段只是文案不是口播 | 下载 mp4 → ffmpeg 抽音轨 → **whisper 转写** |

这三条不是配置问题，是平台设计。所以这个工具的本质是：**用真实浏览器绕过接入限制，用本地 ASR 补上缺失的字幕。**

## 快速开始

```bash
git clone https://github.com/karmagit2025/douyin-account-digest.git
cd douyin-account-digest

pip install -r requirements.txt        # playwright + faster-whisper
# 还要装 ffmpeg： Windows: winget install Gyan.FFmpeg / macOS: brew install ffmpeg

python scripts/dy_report.py --check     # 检查环境
python scripts/dy_report.py --login     # 扫码一次（弹出窗口，用抖音 App 扫）
python scripts/dy_report.py "https://www.douyin.com/user/MS4wLjABAAAA..." --top 20
```

跑完打开 `dy_out/<账号后8位>/material.md`。

> 首次转写会自动下载 whisper 模型（small 约 460 MB），走 `hf-mirror.com` 国内镜像。之后是本地读。

---

## 参数

| 参数 | 说明 |
|---|---|
| `--top N` | 精读最近 N 条（默认 20） |
| `--sample K` | 只精读 K 条，其余只要元数据（**省钱档，建议先跑这个校准**） |
| `--meta-only` | 只抓元数据，不下载不转写（几秒钟，看发布节奏/选题用） |
| `--login` | 只做扫码登录 |
| `--check` | 只检查环境 |
| `--asr-model` | `tiny`/`base`/`small`/`medium`，默认 `small` |
| `--out DIR` | 输出目录 |

## 产物

```
dy_out/<账号后8位>/
├── material.md        ⭐ 唯一要读的入口：账号画像 + 全量元数据表 + 精读转写全文
├── list.json          全量元数据（标题/时长/点赞/发布时间/视频直链）
└── v/
    ├── <id>.mp4       视频
    ├── <id>.wav       16k 单声道音轨
    └── <id>.txt       转写原文
```

`material.md` 是核心设计：**把 30 个 txt 合成一个文件**，让 agent（或你自己）只读一次就能写报告，不用逐个打开。

**断点续跑**：`v/<id>.txt` 已存在就跳过。转写跑到一半断了，重跑不会重来。

## 报告怎么写（这是价值所在）

工具只负责把内容拿到手，**判断和写作是人的事**。同一个素材，不同诉求的产出完全不同：

| 诉求 | 报告形态 | 关键章节 |
|---|---|---|
| 买设备 | **选型指南** | 工艺边界 → 配置矩阵 → 价格锚点 → 验收清单 → 避坑话术 |
| 看同行 | **竞品内容情报** | 产品矩阵 → 话术拆解 → 定价策略 → 他没讲的空位 |
| 摸行业 | **认知梳理** | 主题聚类 → 观点演化 → 分歧点 |
| 追产品 | **演化史** | 用 `list.json` 做时间轴和话题迁移统计 |

三种内容必须齐：**事实层**（能对到具体视频）、**判断层**（你的结论 + 置信度）、**边界层**（哪些没验证、哪些是单一信源）。

`SKILL.md` 里有完整的质量红线，包括转写误听对照表。

## 已知限制（诚实交代）

**1. 未登录只能拿 21 条**
不是账号只有 21 条，是平台限制。`--login` 扫码后能翻到几百条（实测某账号 270 条，回溯 4 年）。

**2. 转写有系统性误听**
中文专业术语错得很规律，且**换哪个模型都会有**：

| 误听 | 正确 |
|---|---|
| 小鞋机 | 桥切机 |
| 剧片 / 巨片 | 锯片 |
| 洗刀 | 铣刀 |
| 研板 | 岩板 |
| 撤量仪 | 测量仪 |
| 无成 | 无尘 |
| 复词 / 复齿 | 复尺 |

**引用原文前必须按上下文校正**，拿不准就标注「未确认」。不要让误听词进报告正文。

**3. 平台风控会变**
今天 headless 能过，不代表下个月能过。本项目用真实浏览器 + 持久化 profile，比手搓签名稳，但不是永久保证。频繁轮询会触发验证码——**它是批处理工具，不是监控工具**。

**4. 视频直链有时效**（小时级）
下载全部失败就重跑一次，会重新抓列表。

**5. 纯音乐 / 无口播视频拿不到内容**
转写只有几个字是正常现象，跳过即可，不是坏了。

**6. CPU 上转写约 1.5–3 倍实时**
20 条约 10–15 分钟。可后台跑，不用等。

## 排错

| 现象 | 处理 |
|---|---|
| 只有 21 条 | 没登录，跑 `--login` |
| `403 / Uifid Not Found` | 不该出现（本工具走浏览器）；出现就重跑 |
| `remote debugging requires a non-default data directory` | 想拿真实浏览器 profile 开调试，被 Chrome 136+ 拦。别这么干，用本工具自己的 profile |
| whisper 下载卡住 | 确认 `HF_ENDPOINT=https://hf-mirror.com`（脚本已设默认） |
| 没有可用浏览器 | Windows 装 Edge；macOS/Linux 装 Chrome |

## 数据与隐私

- 所有数据都在本地：`~/.dsh/dy-digest/`（登录态 profile、模型缓存）+ 输出目录。
- **不会上传任何东西**。工具不调 LLM、不需要 API key。
- 登录态（cookie）**无法从你日常浏览器复制过来**（Chrome 应用绑定加密），只能让本工具自己的 profile 扫一次码。这是设计上的隔离，不是缺陷。
